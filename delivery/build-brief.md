# BMW KZ MVP — Build Brief

## 1. Что строим
Нужно собрать MVP e-commerce сайта для продажи автоаксессуаров BMW по Казахстану.

Не делаем enterprise-комбайн. Делаем быстрый, чистый, premium-looking магазин, который умеет:
- показывать каталог аксессуаров;
- помогать с совместимостью;
- принимать заказы;
- отправлять лиды/заказы в CRM/админку;
- давать быстрый переход в чат.

## 2. Состав первой версии
### Страницы
- Главная
- Каталог
- Категории
- Карточка товара
- Корзина
- Checkout
- Личный кабинет lite
- Доставка
- Оплата
- Возврат
- Контакты
- FAQ

### Категории на старт
- Интерьер
- Экстерьер
- Колеса и сезон
- Уход за BMW
- Электроника и полезные аксессуары
- Lifestyle / подарки

### Минимальный объем каталога
- 50–150 SKU
- для каждого товара: фото, цена, SKU, статус наличия, описание, совместимость, SEO-поля

## 3. Must-have функции
- мобильная адаптация;
- поиск;
- фильтры по категории и модели BMW;
- add to cart;
- guest checkout;
- выбор доставки;
- выбор оплаты;
- CTA “Проверить совместимость”;
- CTA “Написать в WhatsApp/Telegram”;
- передача заказа и лидов в CRM/админку;
- базовая аналитика.

## 4. Ключевые блоки на PDP
- фото;
- название;
- цена;
- наличие;
- совместимость;
- описание;
- доставка/возврат;
- related products;
- кнопка купить;
- кнопка спросить / проверить совместимость.

## 5. Tech direction
Можно идти двумя путями:

### Path A — быстрый кастомный storefront
- Next.js / similar modern frontend
- headless CMS or commerce backend
- custom admin/integration layer

### Path B — ускоренный commerce base
- Shopify-like / WooCommerce-like setup
- кастомная тема
- подключение CRM, analytics, chat, payment

Для старта реализации команда должна быстро выбрать один путь и не прыгать потом туда-сюда.

## 6. Интеграции
- payment provider (минимум 1 рабочий онлайн-метод)
- CRM (amoCRM / Bitrix24 / HubSpot / lightweight internal)
- GA4
- Meta Pixel
- WhatsApp/Telegram contact channel

## 7. Данные, которые должны существовать в модели товара
- id
- sku
- name
- slug
- category
- price
- stock status
- images
- short description
- full description
- fitment tags
- seo title
- seo description

## 8. Что критично для дизайна
- premium feel без перегруза;
- темный/нейтральный clean visual direction уместен;
- сильная mobile UX;
- clear trust blocks;
- не делать дизайн как старый каталог запчастей.

## 9. Что критично для операций
- менеджер должен получать новые заказы быстро;
- заявка на совместимость не должна теряться;
- статусы наличия должны быть честными;
- сложные позиции можно помечать “под заказ”.

## 10. Acceptance criteria первой версии
Считаем версию готовой к soft launch, если:
- пользователь может найти товар;
- открыть карточку;
- понять совместимость;
- добавить в корзину;
- оформить заказ;
- менеджер получает заказ;
- работает как минимум один чат-канал;
- аналитика фиксирует ключевые события.

## 11. Что НЕ надо делать сейчас
- огромный VIN engine;
- сложную warehouse систему;
- многоуровневую лояльность;
- мобильное приложение;
- микросервисы ради понта.

## 12. Первый практический старт команды
1. Зафиксировать стек.
2. Зафиксировать IA и список страниц.
3. Подготовить wireframes.
4. Утвердить data model каталога.
5. Начать параллельно storefront + admin/integration.
6. Наполнить тестовыми SKU.
7. Прогнать checkout и CRM flow.

## 13. Что нужно от бизнеса до начала build
- список стартовых категорий;
- список SKU;
- фото и цены;
- политика доставки/возврата;
- выбранный CRM;
- выбранный payment path;
- кто отвечает за менеджерский чат.
