# BMW KZ MVP — Product Scope

## 1. Цель MVP
Проверить, что нишевый магазин аксессуаров BMW по Казахстану может стабильно конвертировать трафик в:
- заказы;
- заявки на подбор;
- диалоги в мессенджерах;
- повторные покупки.

## 2. Product thesis
Не строим огромный автопортал. Строим понятный премиальный storefront с хорошим UX и поддержкой выбора.

## 3. Основные JTBD
### Для клиента
- Найти аксессуар для своей BMW без боли.
- Проверить, подойдет ли товар к моей модели.
- Быстро заказать с доставкой по Казахстану.
- Получить подтверждение наличия/срока.
- При необходимости быстро перейти в чат с менеджером.

### Для бизнеса
- Быстро запускать ассортимент и лендинги категорий.
- Получать лиды/заказы в CRM.
- Видеть, какие товары/категории продают.
- Не терять покупателей, которые хотят уточнить совместимость.

## 4. In scope for MVP
### 4.1 Storefront
- Главная страница
- Каталог
- Категории
- Карточка товара
- Поиск
- Корзина
- Checkout
- Базовый личный кабинет
- Страницы: доставка, оплата, возврат, контакты, FAQ

### 4.2 Каталог и ассортимент
- 50–150 SKU на старте
- 6–8 ключевых категорий
- теги совместимости
- фильтры по модели/серии/кузову/типу аксессуара
- товары “в наличии”, “под заказ”, “ожидается”

### 4.3 Конверсионные фичи
- CTA “Проверить совместимость”
- CTA “Написать менеджеру”
- sticky add-to-cart на mobile
- upsell / related products
- избранное
- захват лида, если товара нет в наличии

### 4.4 Операционные фичи
- админка для товаров, остатков и заказов
- CRM-передача заказов и лидов
- уведомления менеджеру о новом заказе
- шаблоны order status

## 5. Out of scope for MVP
- полноценный VIN-decoder enterprise-уровня;
- сложная ERP/WMS;
- marketplace multi-vendor;
- глубочайшая локализация на 3+ языка;
- продвинутый loyalty program;
- мобильное приложение;
- полноценный fitment engine для всех поколений BMW с заводскими каталогами;
- сложные подписки/клубные уровни.

## 6. MVP user flows
### 6.1 Каталог → карточка → checkout
1. Пользователь приходит из рекламы/SEO.
2. Заходит в категорию или поиск.
3. Открывает товар.
4. Видит цену, наличие, совместимость, доставку.
5. Добавляет в корзину.
6. Оформляет заказ как гость.

### 6.2 Карточка → проверка совместимости → чат
1. Пользователь сомневается в fitment.
2. Нажимает “Проверить совместимость”.
3. Отправляет модель/год/VIN фрагмент.
4. Менеджер получает заявку с товаром.
5. Пользователь продолжает покупку после подтверждения.

### 6.3 Нет в наличии → заявка
1. Товар под заказ или out of stock.
2. Пользователь оставляет телефон/мессенджер.
3. CRM создает lead с SKU и источником.
4. Менеджер связывается вручную.

## 7. Структура MVP-функционала по приоритету
### P0 — must have
- каталог + категории;
- карточка товара;
- корзина + checkout;
- guest checkout;
- выбор доставки;
- выбор оплаты;
- заказ уходит в CRM/админку;
- чат-кнопка;
- базовые SEO-friendly URL;
- mobile UX.

### P1 — should have
- фильтры по модели/серии;
- избранное;
- личный кабинет с историей заказов;
- заявки на совместимость;
- related products;
- промо-блоки на главной.

### P2 — nice to have
- bundle offers;
- отзывы;
- блог/гайд-страницы;
- простая программа лояльности;
- сравнение товаров.

## 8. Требования к карточке товара
Каждая карточка должна содержать:
- название товара;
- артикул / SKU;
- цену;
- статус наличия;
- галерею фото;
- краткое УТП;
- описание;
- список совместимых моделей;
- опции/варианты (если есть);
- доставка/самовывоз;
- гарантия/возврат;
- CTA “В корзину”;
- CTA “Проверить совместимость”;
- CTA “Спросить в WhatsApp/Telegram”.

## 9. Checkout requirements
MVP checkout должен быть коротким.

### Поля
- имя;
- телефон;
- email опционально;
- город;
- адрес или пункт выдачи;
- способ доставки;
- способ оплаты;
- комментарий;
- согласие с политикой.

### Способы доставки
- курьер по городу;
- доставка по Казахстану;
- самовывоз;
- для части позиций — “под заказ, срок уточнит менеджер”.

### Способы оплаты
- банковская карта;
- Kaspi / локальные методы при наличии интеграции;
- перевод / счет для ручной обработки на первом этапе.

## 10. Личный кабинет
Минимум:
- вход по email/телефону + одноразовый код или passwordless later;
- список заказов;
- статусы заказов;
- сохраненные данные;
- избранное;
- гараж пользователя: мои BMW.

## 11. CRM requirements
Обязательные поля в заказе/лиде:
- order id;
- дата;
- источник;
- UTM;
- клиент: имя/телефон/email;
- город;
- товары;
- сумма;
- статус оплаты;
- статус доставки;
- заметка про совместимость;
- preferred messenger.

## 12. Success metrics
### Коммерческие
- conversion rate;
- add-to-cart rate;
- start checkout rate;
- completed order rate;
- revenue per visitor;
- lead-to-order conversion.

### Операционные
- время ответа в чат;
- доля заказов с ручной проверкой совместимости;
- % отмен из-за отсутствия наличия;
- средний срок доставки.

## 13. Recommended MVP stack decisions
- не перегружать первую версию кастомом;
- использовать headless/lightweight storefront или простой современный e-commerce stack;
- CRM и чат должны быть быстрее, чем идеальный дизайн;
- каталог и контентная модель должны позволять быстро расти после MVP.
